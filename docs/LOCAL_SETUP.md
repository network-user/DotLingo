# Локальный запуск на Windows

## Требования

- Windows 10/11 x64.
- CPython 3.12 или 3.13. Ограничение указано в `pyproject.toml`.
- Microsoft Edge WebView2 для графического интерфейса (pywebview). На Windows 11 и обновлённой Windows 10 он уже установлен; иначе скачайте Evergreen-установщик с сайта Microsoft: https://developer.microsoft.com/microsoft-edge/webview2/.
- Интернет нужен только для установки Python-пакетов и явной загрузки выбранной модели. После установки runtime и модели перевод выполняется локально.

Проверьте Python:

```powershell
python --version
```

Если `python` не найден, установите CPython 3.12 или 3.13 x64. Команда `py -3.12` может использоваться вместо `python`, если Python Launcher видит установленную версию.

## Создать окружение и установить пакеты

В PowerShell откройте корень репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev,pdf]"
```

Это устанавливает приложение в editable-режиме, `pywebview` (окно и HTTP-раздача web UI), пакеты разработки, `pypdf` для PDF с текстовым слоем и зависимости чтения DOCX. Если политика PowerShell запрещает активацию, вызывайте интерпретатор напрямую:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev,pdf]"
.\.venv\Scripts\python.exe -m dotlingo
```

## Запустить

```powershell
python -m dotlingo
```

Приложение создаёт проекты, настройки и скачанные модели в `%LOCALAPPDATA%\DotLingo`. Для отдельного каталога данных:

```powershell
python -m dotlingo --data-dir "D:\DotLingoData"
```

Для headless-проверки без окна (CI, окружение без WebView2):

```powershell
python -m dotlingo --smoke-test
```

Команда прогоняет проверки моста `api.py` и печатает JSON-результат; окно не открывается.

## Включить CPU inference

Графический интерфейс запускается без модели. Для перевода нужен optional backend `llama-cpp-python`. Кнопка в настройках или на первом запуске скачивает закреплённое колесо по фиксированному адресу, сверяет SHA-256 и только потом вызывает pip. Переменные `PIP_*` в этот запуск не передаются.

Это ставит runtime, но не скачивает модельные веса. В приложении откройте страницу моделей, проверьте размер и лицензию и подтвердите выбранную загрузку. Загрузка весов требует сети и свободного места; после её завершения перевод возможен офлайн.

При первом запуске приложение измеряет всю RAM устройства, свободное место, число CPU-потоков, NVIDIA GPU (включая свободную VRAM) и возможности backend. Кэш показывается сразу, а на каждом запуске замер повторяется. Автоподбор предлагает модель Hy-MT2 по всей RAM с резервом 1 ГБ и месту на диске; тот же резерв использует вердикт «не помещается». Свободная RAM на отказ не влияет, но низкий остаток показывается предупреждением. Это не оценка качества. CPU-потоки подбираются автоматически (до 8, оставляя один логический поток системе). Слои уходят на GPU, только если свободная VRAM дискретной карты покрывает расчёт модели и запас 1.4 ГБ. На CPU батч 256 и контекст не длиннее 4096. Если llama.cpp не найден, кнопка в настройках или на первом запуске ставит CPU-колесо после проверки SHA-256, а при дискретной NVIDIA и Python 3.10-3.12 ещё и CUDA cu124 с закреплёнными колёсами `nvidia-cublas-cu12` и `nvidia-cuda-runtime-cu12`. Setup.exe ставит то же CPU-колесо через эту проверку и CUDA не скачивает.

Своя модель добавляется на странице «Модели» через выбор локального `.gguf` файла. DotLingo копирует файл в каталог моделей после отдельного подтверждения, затем проверяет размер и SHA-256. Исходник остаётся на месте. Языковые коды и контекст берутся из сведений, введённых пользователем; формат chat template и работу модели нужно проверить запуском задачи.

Текущая совместимость `llama-cpp-python` с конкретными весами ещё не проверена на Windows. Сведения о закреплённых ревизиях и статусах моделей находятся в [MODEL_MATRIX.md](MODEL_MATRIX.md). Сборочный сценарий описан в [BUILD_WINDOWS.md](BUILD_WINDOWS.md): зависимости ставятся без индекса llama.cpp, затем то же закреплённое CPU-колесо.

## Проверки разработчика

```powershell
python -m pytest -q
python -m ruff check src tests
```

Для импорта PDF нужен extra `pdf`. PDF fixture-тест использует PyMuPDF (`fitz`) только для создания тестового файла и пропускается, если пакет отсутствует; приложение читает PDF через `pypdf`. UI smoke выполняется headless через мост (`python -m dotlingo --smoke-test`) и не требует окна. Установка проекта не запускает тесты и не загружает модели.

## Обновление клона

Если приложение запущено из git-клона, при старте оно сравнивает текущий коммит с `origin/main`. Галочка «Проверять при запуске» в настройках это выключает. Новые коммиты не ставятся сами: кнопка «Обновить» делает `git fetch`, `reset --hard` и `pip install -e ".[pdf]"`. То же выполняет `deploy\update.ps1`. Проекты и модели в `%LOCALAPPDATA%\DotLingo` не меняются. Локальные правки в клоне сбрасываются только после подтверждения. Установленный Setup.exe этой проверкой не обновляется.

## Данные и ограничения

- Не удаляйте `.venv`, пока в нём идёт установка пакетов.
- Веса моделей не входят в репозиторий и приложение; пользовательские данные хранятся вне `.venv`.
- PDF импортирует текстовый слой. Пустой пароль пользователя снимается сам; пароль на открытие нужно снять заранее. Книга со шрифтом полосы ModernMT возвращается PDF, прочий текстовый PDF собирается новым PDF. Скан читается Windows OCR и возвращается картинкой страницы. Язык распознавания должен быть установлен в Windows.
- Для сборки Setup.exe скрипт сам ставит PyInstaller. Inno Setup 6.7.3 скачивается в `build\tools`, если `ISCC.exe` ещё нет. Чистая Windows-установка пока не проверена. Готовую сборку ставит `Install.bat`: ярлык на рабочем столе и в меню «Пуск».
