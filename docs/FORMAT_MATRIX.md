# Матрица форматов

Значок «тесты» означает локальные тесты фикстур, а не проверку каждого варианта стандарта. Импорт парсера не гарантирует качественный обратный экспорт.

| Формат | Импорт | Экспорт | Что сохраняется | Ограничения | Зависимости | Проверки |
|---|---|---|---|---|---|---|
| TXT | Да, UTF-8/UTF-8 BOM и CP1251 | TXT | Порядок абзацев и точные разделители строк/пробелов | Неизвестная кодировка отклоняется; нет метаданных/стилей | Стандартная библиотека | Round-trip CRLF/пробелов и CP1251 |
| Markdown | Да, `.md`/`.markdown` | `.md` или `.txt` | Заголовочные уровни, маркеры списков/цитат, fenced code, пустые блоки | Inline Markdown остаётся частью текста модели; переносы строк внутри прозы могут измениться; HTML/raw blocks не разбираются полностью | Стандартная библиотека | Заголовки/кодовая ограда; fixture |
| DOCX | Да | DOCX, TXT, Markdown | Параграфы, заголовки, таблицы и их контейнеры; при DOCX-экспорте остаются стили исходного документа | Runs внутри абзаца сливаются в первый текстовый run; inline-жирность/курсив и другие отличающиеся участки могут потеряться. Header/footer, текстовые поля, сноски и изображения не входят в дерево | `python-docx`, `lxml` | Документ с таблицей: импорт → изменённый DOCX → исходник хеширован |
| EPUB | Да | EPUB, TXT, Markdown | Порядок spine, XHTML-файлы, архивные ресурсы и ссылки вне переведённых text nodes | Inline spans flatten до простого текста; сложная вложенная разметка может упроститься; CSS/скрипты/изображения не переводятся | `zipfile`, XML из stdlib | Книга с двумя главами, text nodes и непереводимым SVG asset |
| PDF с текстовым слоем | Да. Пустой пароль пользователя снимается, пароль на открытие отклоняется | Книга со шрифтом полосы ModernMT: тот же PDF. Иначе новый PDF с текстом, а также TXT или Markdown | У книжной укладки: иллюстрации, полоса и номера страниц. Абзац, который не входит в строку, дописывается в конец того же PDF. Иначе текст и границы страниц | Укладка не обещает произвольный офисный PDF. Если в файле есть страница почти без текста, весь PDF уходит в режим скана | `pypdf`, для укладки ещё `pdfminer.six`, `reportlab`, `pypdfium2` | Текстовый PDF без полосы собирается новым PDF. Книжная полоса, слишком длинный абзац и пустой пароль: отдельные тесты |
| PDF-скан или смешанный PDF | Да. Страница почти без текста читается Windows OCR. Язык берётся из языка проекта, без проекта - из языков Windows | PDF остаётся картинкой страницы, перевод пишется в те же строки. Также TXT, Markdown и остальные сборки из текста | Изображение страницы. Текст, который не вошёл в строки, дописывается в конец PDF | Нужен установленный в Windows язык распознавания. Колонки и порядок зависят от OCR. Tesseract не входит | `pypdfium2`, `winocr`, Pillow, Old Standard | Скан с подменённым распознаванием: перевод появляется на странице. Пустая страница даёт честную ошибку |

## Распознавание скана

Скан и смешанный PDF растеризуются через `pypdfium2`. Строки читает системный Windows OCR (`winocr`), не отдельный Tesseract. Языковые данные - это языки, уже добавленные в Windows. На странице с текстовым слоем внутри такого файла рамки берутся из слоя, а не из OCR. Перевод стирает исходные строки и набирается Old Standard в те же рамки. Качество распознавания этот репозиторий не измеряет.

`pypdf` выбран вместо PyMuPDF: последний распространяется под AGPL-3.0 или коммерческой лицензией Artifex, что добавило бы лицензионные условия к standalone-сборке. [pypdf license](https://pypdf.readthedocs.io/en/latest/meta/faq.html), [PyMuPDF licensing](https://pymupdf.readthedocs.io/en/latest/about.html).

## Общая сборка из уже прочитанного текста

Конвертер и экспорт перевода могут собрать новый файл из блоков, которые импорт уже достал. Это не копия вёрстки.

| Куда | Что получается | Чего нет |
|---|---|---|
| TXT, Markdown | Абзацы и заголовки | Стили, картинки, колонки |
| HTML | Одна страница со заголовком и абзацами | CSS исходника, картинки |
| RTF | Текст, который открывает Word | Жирный, курсив и таблицы исходника, если файл собран заново |
| FB2 | FictionBook: название, заголовки, абзацы | Обложка, сноски, картинки |
| ODT | Текст OpenDocument | Стили абзацев исходника |
| DOCX | Из DOCX остаются абзацы и таблицы. Из другого файла собирается новый документ | Колонтитулы, сноски и рисунки даже у исходного DOCX |
| EPUB | Из EPUB остаётся книга. Из другого файла собирается одна глава | Сложная вложенная разметка упрощается |
| PDF | Книжная полоса только у PDF с этим макетом. Скан остаётся картинкой страницы. Иначе новый текст на страницах A4 | Для сборки нужен пакет `pdf` |
| JSON | Список блоков с видом и текстом | Страница для чтения |

Исходный файл конвертер не перезаписывает. Если имя занято, к результату добавляется `.converted`.

## Новые адаптеры

Адаптер должен вернуть `ParsedDocument` с упорядоченными `Block`, section id/title и format locator; export writer должен получить исходный файл, нормализованное дерево и карту переводов, записать новый файл и пройти fixture round-trip. Новый формат сначала включается в матрицу с ограничениями и отдельными импорт/экспорт-тестами, затем становится доступен в UI.
