## Аппаратные профили

Это рекомендации размещения, не рейтинг качества и не запрет ручного выбора. Автоподбор берёт модель каталога с наибольшей расчётной RAM, которой хватает места и резерва 1 ГБ. По текущим оценкам это 7B Q4_K_M, затем TranslateGemma 4B, затем 1.8B Q8_0 и 1.8B Q4_K_M. У TranslateGemma нет оценки VRAM, поэтому слои GPU для неё не включаются.

Размер файла берётся из закреплённого артефакта. Загрузчик требует ещё запас на временный файл. RAM/VRAM Hy-MT2 в реестре - инженерная оценка для контекста 8192, у TranslateGemma - для 2048. Это не требование производителя и не замер DotLingo.

CPU-потоки: число логических процессоров минус один, не больше 8. GPU: если сборка llama.cpp умеет offload и свободная VRAM дискретной карты покрывает расчётный объём модели с запасом 1.4 ГБ, на GPU уходят все слои. Если VRAM хватает только на часть, уходит доля слоёв по этому бюджету. Встройка и карта меньше 1.5 ГБ остаются на CPU. Если при старте GPU не хватает памяти, задача один раз повторяет загрузку на CPU и укорачивает окно до 4096. На CPU батч 256, с GPU 512. Пользовательский GGUF без оценки VRAM остаётся на CPU. Ни один из этих путей на Windows с реальным весом не прогонялся.

Подтверждённые правки проекта подмешиваются в промпт как короткие примеры с общими словами. Рядом с фрагментом держится окно недавнего перевода по размеру контекста модели. Для окна от 4096 задача хранит короткую память книги и обновляет её по ходу. Скорость и качество на длинной книге не измерялись.
